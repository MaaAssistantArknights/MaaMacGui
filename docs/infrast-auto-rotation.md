# 自定义基建计划：自动选班与时间建议

在基建计划中选择“自动”，会在用户启动流程、GUI 提交基建任务参数时，根据上次成功计划选择后一项。支持任意计划数量和名称，按 JSON 数组顺序循环。没有有效历史时继承当前具体计划，无有效索引时从首项开始。

自动选班不启动流程、不修改定时任务，也不进行任何新的游戏识别。用户选择具体计划时继续执行原版行为。新增的常驻信息在两种模式下都显示：上次换班、本次换班、下次建议班型与时间。

建议时间按最近成功完成时间加该班 duration（分钟）计算，也可设置统一间隔。只粗略按固定周期安排；提前或迟到执行后重新开始计时，不补跑、不跳班、不估算技能或心情。两班不等于每天两换。无有效时长不影响自动选班，只不显示时间建议。支持正数、最多一年（525600 分钟）的间隔。

记录只代表 MAA 的任务完成事件，不证明游戏当前在岗配置。失败或取消不推进新功能的状态。手动执行具体计划成功后也更新历史，切回自动时据此继续。

“自动”明确按顺序选班，不根据 period 选班。其他现有模式不变。升级后不默认开启自动，不修改排班 JSON。

## 实现

- InfrastRotation.swift：GUI 状态、时长验证、指纹和纯计算。
- InfrastConfiguration.swift：可选 rotation 配置；params 过滤该 GUI 元数据，Core 仍收到具体 plan_index。
- MAAViewModel.swift：提交时捕获不可变运行快照；完成/失败时消费一次；按任务、配置及连接隔离。
- MaaMessage.swift：将已有任务事件连接到记录更新，不新增 Core 协议。
- InfrastSettingsView.swift：下拉“自动”、常驻状态、可选统一间隔。
- MAATask.swift：配置与完成记录同一次原子写入，避免一半更新。

文件指纹为原 JSON 字节的 SHA-256；任何文件修改都让旧记录不再适用于新建议。连接信息只用来隔离本地历史，不上传。无法识别同一连接背后用户手动切换游戏账号，换账号后应重新建立一次成功记录。

## 验证

运行 `bash Tests/InfrastRotation/run.sh`。该脚本用 Command Line Tools 编译实际计算、配置、界面源码；生命周期测试提取生产提交/完成方法，使用假 Core 验证。它不等同于构建完整 MAA，也不验证真实 Core 的回调分发。

本实现由 GPT-6 Astra 协助编写。已使用 Xcode 26.6 和官方 MAA 6.17.5 运行库完成 arm64 Debug / Release 构建，并在 PlayCover 完成一次真实基建换班，验证具体索引提交、成功记录、24 小时建议及重启持久化。Windows 需单独适配 WPF，不能将 Mac 测试当成 Windows 验证。
