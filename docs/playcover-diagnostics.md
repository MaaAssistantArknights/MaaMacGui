# PlayCover 环境检测

入口：实用工具 → PlayCover 环境检测，位于分辨率指南旁。

默认直接读取 `/Applications/PlayCover.app` 和 `~/Library/Containers/io.playcover.PlayCover/`，首次读取时由 macOS 处理“允许访问其他 App 数据”的系统授权，不再主动弹出目录选择窗口。已允许访问时系统可能不再询问；拒绝或读取失败会标记“无法检测”，不会误判为已通过。MAA 保留沙盒，仅为上述两个固定位置声明只读路径例外，不申请其他容器的沙盒读取权限。

非默认安装位置或默认路径访问失败时，可展开“检测路径”手动选择应用或数据目录；这种方式仅保存只读 security-scoped bookmark。应用重启后恢复手动选择的路径，授权失效时使用默认路径并提示；点击“恢复默认路径”可清除保存的授权。系统权限是否记忆、是否再次询问取决于 macOS 与应用签名；本地临时签名测试包不能替代正式签名的权限验证。

真实用户目录通过 POSIX 账户数据库 `getpwuid_r` 获取，避免 Foundation 的用户目录 API 在沙盒内重定向到 MAA 自身容器。读取失败的检查项包含实际尝试读取的路径，复制报告时仍将真实用户目录替换为 `~`。`NSAppDataUsageDescription` 说明读取 PlayCover 安装与配置的用途；系统已允许访问时可能不会再次弹窗，弹窗未出现不能单独作为权限失败的判断依据。

游戏未启动时，先检查发行信息、游戏安装、PlayCover 开关与图像配置、MAA 连接设置。“启动游戏并继续检测”按钮始终可见，可在第一次检测前点击；MAA 执行任务或检测期间按钮禁用。用户点击后先完成静态读取，再按当前客户端启动游戏并最多等待服务 20 秒；已运行的游戏只继续检测，不重新启动。游戏无法定位时说明具体失败项，超时后保留静态结果，可再次继续或重新检测。MAA 执行任务时只进行静态检查，开始执行任务或离开页面会取消运行检测。

IPv6 回环地址可用于诊断探测和端口比较，但当前 Core 的地址解析不支持 IPv6，MAA 设置会单独提示改用 `localhost` 或 `127.0.0.1`。

图像配置检查保留独立结果，实际截图的尺寸、16:9 与最低 720p 判定和分辨率指南共用。诊断按当前 MAA 模式检测 RGBA、BGR 或 MacSCK；原指南继续使用 BGR。协议 v2 的 RGBA 可用，但游戏标识检查显示无法检测。结果通过仅代表该检查已通过，不承诺所有任务或图像识别均正常。

检测按前置条件分支执行：MaaTools 关闭/未知、游戏或 PlayTools 未就绪、端口非法时跳过服务和截图；握手、身份、尺寸或窗口采集失败后不再请求其后续项目。跳过项目显示“无法检测 · 已跳过”并指出前置原因。静态图像配置与推荐开关独立检查；单个配置字段损坏不会抹掉其他字段。全部依赖与例外见 [检查依赖分析](playcover-diagnostic-dependencies.md)。

MAA 版本仅按 PlayCover 版本号是否包含 `maa` 判断（不区分大小写），不再要求 Bundle ID、更新源或更新公钥匹配。版本号缺失、空白或类型无效时标为无法检测；随附 PlayTools 和运行协议兼容性分别检查。未知字段、读取失败和未完成检查不会默认通过。超过配置/加载项读取预算或图片内存上限时标为无法检测，不推断为文件损坏。

复制报告只包含版本、客户端、所检查的设置、结论和错误阶段；用户目录替换为 `~`，不附游戏截图、账号或完整配置。

## 开发验证

在已配置完整 Xcode 的环境中，从 MaaMacGui 根目录运行：

```sh
swift test
```

静态检查按应用、游戏安装、游戏配置分阶段执行；路径始终取默认值或手动选择值，读取失败由对应阶段报告。游戏配置只解析一次，并独立校验各字段类型，避免一个损坏字段影响其他检查。

独立 Swift package 直接编译实际诊断源文件，不依赖 MaaCore 二进制或已安装游戏。测试使用配置样本和本机随机端口模拟 MaaTools 服务，不修改真实游戏或 PlayCover 设置。

发布前仍需使用启用沙盒的正式签名 Release 验证：默认路径的系统 App 数据权限允许/拒绝、应用重启后的权限恢复、自定义路径 bookmark 恢复与失效、客户端启动、录屏权限拒绝与恢复、真实 RGBA/BGR/MacSCK 截图，以及原分辨率指南的预设建议与截图展示。
